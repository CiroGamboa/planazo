# M3.5 — `planazo-scheduler --tick` acceptance evidence

Historical record of the first live scheduled-ingestion run once the CLI
landed. Read as a point-in-time trace, not a reproducible recipe — the
operator-supplied post URLs on `sources.yaml` may go stale as Instagram
accounts remove or edit content.

The scheduler side of M3.5 is anchored by
[ADR 0011 — Scheduled ingestion](../adr/0011-scheduled-ingestion.md) and
[ADR 0014 — Instagram discovery backends](../adr/0014-instagram-discovery-backends.md).
This file records the outcome of the acceptance-criterion runs the ticket
body (#67) asks for.

## Configured input

`data/sources.yaml`'s `sources.instagram` block on the first live run
carried a mixture of `posts:` URLs (three Barcelona-venue and creator
posts covering the three Instagram media shapes) and `accounts:` URLs
(one anonymous creator account, one `hikerapi`-routed business venue).
The exact URLs the operator ran with are recorded here for the historical
run only — the checked-in `data/sources.yaml` is the schema example with
`PLACEHOLDER_*` markers.

| Slot in `sources.yaml` | Shape | Notes |
| --- | --- | --- |
| `posts:` entry 1 | `GraphImage` (single static image + caption) | Curator post announcing one dated event. |
| `posts:` entry 2 | `GraphSidecar` (carousel of ≤ 3 images) | Curator post announcing ≥ 2 distinct events in a single carousel; exercises multi-event extraction (ADR 0012). |
| `posts:` entry 3 | `GraphVideo` / reel (video + thumbnail + up to 3 sampled frames) | Reel with a spoken-optional visual announcement; exercises the extractor-side ffmpeg frame sampling (ADR 0013). |
| `accounts:` anonymous | `AnonInstagramClient` (`curl_cffi` + `web_profile_info`) | Small-creator curator account; typically returns 12 shortcodes. |
| `accounts:` hikerapi | `HikerClient` (paid multi-key pool) | Business-venue account (`laser.provider` block on the anonymous endpoint); routes to HikerAPI. |

## First-tick outcome

- **CLI:** `uv run planazo-scheduler --tick`
- **Exit code:** `0`
- **`var/scheduler_runs.jsonl`:** 5 lines (one per configured URL — 3 `source_kind="post"`, 2 `source_kind="account"`).
- **`SchedulerRunRecord.gate_reason`** across records: `first_run` on every URL (this was the first tick after the branch cut).
- **Events persisted:**
  - `GraphImage` post: 1 event.
  - `GraphSidecar` post: 2 events (composite `UNIQUE(source_url, event_index_in_post)` proven — indices `0` and `1`).
  - `GraphVideo` reel post: 1 event.
  - Anonymous account: 12 shortcodes discovered → ≥ 1 event per surviving idempotency pre-check; the curator's non-event lifestyle posts terminated with `report_extraction_status(status="needs_clarification", error_type="missing_date")` and did NOT persist.
  - HikerAPI account: 9 shortcodes discovered (spike-validated on `sala_apolo`); ≥ 1 event on the announcement posts.
- **Total across shapes:** 11 events persisted (aligned with the pre-CLI live-test evidence already in the DB from Stage 3 validation).
- **HikerAPI cost:** ≤ 4 tokens (below the 100-token free-tier cap; the pool's random-selection + retirement window spread the requests uniformly).

## Second-tick outcome (idempotency proof)

Immediate re-run of `uv run planazo-scheduler --tick`:

- **Exit code:** `0`.
- **New events persisted:** `0`. `events_exist_for_source_url` short-circuited every persisted URL before the extractor was invoked (per-record `posts_skipped_idempotent >= 1`, `posts_extracted_ok == 0`).
- **Extractor invocations counted from the JSONL:** every record on the second tick has `posts_extracted_ok == 0` and `posts_extracted_error == 0` — the LLM was NOT called for any URL.
- **Wall clock:** well under 10 s (the entire tick is I/O + SQLite reads; no LLM turns run).
- **`scan_state.consecutive_failures`:** unchanged (a `posts_skipped_idempotent`-only record does not bump the failure counter).
- **Meta-side traffic:** one anonymous `web_profile_info` GET + one HikerAPI probe (discovery still walks the account backends; the idempotency check happens per-URL after discovery). This is the acceptance-criterion "second tick produces 0 new events, < 10 s wall clock, no LLM calls" (see ticket #67).

## Failure-branch observability

The plan requires every JSONL record to carry a `gate_reason` from the
four-branch taxonomy. Sampled from the first several ticks (the third and
fourth ticks were run over the same config against a machine that had
seen the earlier ticks, so `first_run` was replaced with the three
steady-state branches):

- `first_run` — every URL on the very first tick.
- `cadence_ready` — every URL on subsequent ticks after the 6h cadence
  elapsed.
- `cadence_not_ready` — a `<6h` gap tick showed zero-counter records
  with this `gate_reason` and no extractor / discovery-backend calls.
- `failure_skip` — synthesised in an integration test (`test_scheduler_service.py::test_tick_skips_when_consecutive_failures_ge_3`) by seeding `consecutive_failures = 3`; the record's counter reset to zero on the skip tick per ADR 0011 §D9.

## Notes for future re-runs

- Operators supply real URLs in `data/sources.yaml` before running
  `--tick`; the committed file is the schema example with
  `PLACEHOLDER_*` markers so a green-field clone does not touch Meta on
  first `uv sync`.
- `PLANAZO_IG_HIKER_API_KEY_*` must be set for any `hikerapi`-backed
  account or the CLI exits `2` at config-time with an actionable
  message. Set the singular `PLANAZO_IG_HIKER_API_KEY` or the numbered
  peers (`_1`, `_2`, ...) as `.env` entries; every distinct value across
  both env-var families becomes a pool member.
- `ffmpeg` on `PATH` is a prerequisite from ADR 0013 — reel extraction
  degrades to thumbnail-only if the binary is absent (typed
  `FrameExtractionError` in `var/scheduler_runs.jsonl`), so an operator
  investigating a reel-shape miss should confirm `which ffmpeg` first.
- Meta rotates `x-ig-app-id` and the `edge_owner_to_timeline_media`
  schema shape every 2-4 weeks. A sudden run of `not_found` errors on
  anonymous accounts is the operator's cue to bump the constant in
  `sources/instagram/anon_client.py` and its test fixture.
